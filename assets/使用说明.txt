NPA v__NPA_VERSION__ 全平台包
================================================

文件
----
bin/
  npa-darwin-arm64        macOS（Apple Silicon）
  npa-darwin-amd64        macOS（Intel）
  npa-linux-arm64         Linux ARM64
  npa-linux-amd64         Linux x86_64
  npa-windows-arm64.exe   Windows ARM64
  npa-windows-amd64.exe   Windows x64
  npa-windows-386.exe     Windows 32 位
run.sh                    macOS / Linux 一键启动（自动匹配平台）
run.bat                   Windows 一键启动（自动匹配架构）
data/                     可选的本地状态目录（配合 --data-dir data 使用）
LICENSE                   MPL 2.0 许可证
使用说明.txt              本文件

全部二进制为纯 Go 构建（CGO_ENABLED=0），单文件即可运行，无需安装运行时。

启动
----
Windows：双击 run.bat，或在 PowerShell 中执行
    .\run.bat
    .\bin\npa-windows-amd64.exe

macOS / Linux：终端执行
    ./run.sh
    ./bin/npa-darwin-arm64        # 或对应平台的二进制

启动后访问：
    Web: http://127.0.0.1:56700   （固定回环，管理面不对外）
    节点通信: http://<本机IP>:56701（调试期默认局域网，可在设置改回仅本机）

本包启动的两个监听点：
    56700/tcp  Web 管理界面与 REST，仅 127.0.0.1
    56701/tcp  节点通信端口：MCP（/mcp）+ 子网节点注册 / 长连接 / 数据连接池 /
               按需直连协调 / 一次性下载端点，全部按路径分发，默认局域网

端口说明：56710（旧版的独立反向接入端口）已合并进 56701。
旧版节点的上级种子若写的是 :56710，新版会自动按 56701 处理，无需修改。

端口映射（远程子网设备，例如 RustDesk）
----------------------------------------
适用于「本机无法直连子网设备，但子网内的 NPA 节点可以」的场景。
若本机连子网也进不去，先做下面的「子网节点反向上级」，再回来建映射即可：

1. 打开 Web 的「端口映射」页，新建映射：
     子网目标 IP   例如 192.168.50.21
     目标端口      RustDesk 默认 21115
     本机端口      填 0 表示自动分配，也可指定空闲端口
2. 保存并启动，列表会显示「本机端口 → 目标 IP:端口」以及当前经由
   （直连，或某个已授权的中继节点）。
3. 在本机 RustDesk 客户端连接 127.0.0.1:<本机端口>，即可远程该设备。
4. 需要固定走某个中继节点时，在「经由节点」里选择它；不选则自动选路。

端口映射与「隧道」页的 SSH Local/Remote/SOCKS 相互独立，删除隧道不影响映射。
本机映射默认仅监听 127.0.0.1；只有在单条映射上显式开启局域网监听后，
同网段其他机器才能连接该端口。

上级网络自动发现（无种子时）
--------------------------------
规则：有种子就只用种子；没种子（也没填探测网段）且开关开着时自动发现。

1. 节点页「无种子时自动发现上级」默认开启（设置键 peer_auto_discover_uppers）。
2. 自动流程：先 traceroute（前 6 跳）取路径上第一个不属于本机网段的私网地址，
   它所在 /24 视为候选上级网段；再对该网段只探 56701 并用 /api/info 校验，
   命中第一个网段即停。全程只发出站请求。
3. 结果每 10 分钟刷新一次，自动并入拓扑查询、分域选举与增量推送。
4. 边界：家用 NAT / 单路由直连出口的拓扑探测不到（没有第二跳私网地址），
   这种情况仍需在「上级种子」里填一次上级地址。
5. 探测会向候选网段扫一个端口，介意的话把开关关掉，只用手工种子/网段。

子网节点反向上级（跨网段，本机发现不到子网时用）
--------------------------------------------------
mDNS 只在同一广播域有效，本机（如 192.168.0.165）主动发现不到子网节点
（如 192.168.2.192）。这时反过来做：子网上的 NPA 主动发现本机并注册。

1. 本机（上级）：打开「节点」页，确认「反向接入」卡显示本机入口
       192.168.0.165:56701
2. 子网机器（下级）：解压本包并启动，进入「节点」页，填：
       上级种子        192.168.0.165:56701
   或填 上级探测网段    192.168.0.0/24   （只扫显式配置的网段，留空不扫描）
   保存并重启发现后，本机的「已注册到本机的子网节点」里会出现它。
3. 之后本机侧即可反向使用该节点：端口映射、Local/SOCKS 隧道、Web 代理、
   命令执行、交互终端、文件读写，能力与 SSH 节点等价。
4. 所有连接都由子网侧发起，本机不要求子网开放任何入站端口。
5. 注意：反向接入注册当前不鉴权，同网段任何机器都能注册并被反向拨号；
   正式使用前请收紧。
6. 每个下级节点只注册到一个上级：发现到多个候选上级时按「种子优先 + RTT
   最短」选定一个；当前上级不可用才会切换到下一个。链路挂在谁那里，
   就只有谁（及经它授权的节点）能使用这个下级。

跨域访问（上级的上级）
--------------------
节点挂在别的上级下、与本机不相连时，按拓扑自动兜底：
1. 本机先查目标节点在拓扑里的持有上级，经它协商出一条反向代理管道；
2. 文件与命令走节点自己的 56701 上的 /api/file/* 与 /api/exec（纯 HTTP、流式，
   不占通道池），隧道/端口映射/Web 代理共用同一条拨号入口；
3. 多跳 A→B→C 逐跳递归，A 不需要能直连 C，只要链上每一跳都能出站。
3 节点以上时建议在顶层设 peer_relay_fallback=true（默认已开）；
若某个中间上级的地址是内网不可达的，在它上面设置 peer_advertise。

节点拓扑与按需直连（P2P）
--------------------------
「概览」页的拓扑图为完整树状视图：
  本机（根）→ 已注册的下级节点 → 下级自报的它的下级 → …
  同时显示本机的上级节点（若本机作为下级注册过）。

访问不在本机的节点时，NPA 按拓扑自动协商链路：
  1. 直连优先   经拓扑通知目标节点「主动连接本机」，建立临时直连链路，
                用完自动断开（默认空闲 60 秒回收）；
  2. 代理兜底   直连不通（跨独立子网）时，经拓扑中共同上级的中继链路转发。
两种方式对上层能力（命令执行、文件、端口映射、隧道）完全透明，
仅拓扑悬停/详情里的链路描述不同（直连 / 经 <节点> 代理）。

发现节点自动清理
----------------
mDNS/探测发现、从未纳管的节点，若超过 6 小时没有任何再发现记录，
会被自动从节点列表移除，避免网卡变更导致的重复旧记录堆积。

节点在线状态
------------
节点列表与拓扑里的"在线/离线"是实时判断的：
  反向接入（peer）节点 → 看反向链路是否在线（最准确）
  其他节点            → 并发探测它的 SSH / peer / MCP 端口（600ms，结果缓存 5 秒）
  mDNS 发现的节点      → 广播在 3 分钟内也视为在线（Web 默认只监听回环，端口可能探不到）
本机重启后，未重连的反向节点会被标记为离线，等它们重新接入。

节点发现与中继（同一广播域）
----------------------------
1. 打开「设置」，开启 Discovery 服务。
2. 另一台运行 NPA 的机器同样开启后，双方通过标准 mDNS/DNS-SD 发现彼此：
     服务类型：_npa._tcp.local.
     标准端口：5353/UDP（不占用 NPA 私有端口）
3. Windows 防火墙需允许 mDNS/UDP 5353 的专用网络访问。
4. Relay 需要节点显式允许 relay 能力，且相关操作均写入审计日志。

本机管理（Web 设置页）
----------------------
节点版本    节点详情显示对端自报版本；比本机新时带「有新版本」标识
开机自启动  Windows 写注册表 Run，macOS 写 LaunchAgent，Linux 写 systemd user
            （无可用用户实例则回退 XDG autostart）；关闭会把启动项删掉
隐藏控制台  开启后由 run.sh / run.bat 转为后台异步启动，输出只进
            <数据目录>/npa.log，控制台可以直接关闭；关闭后恢复前台双输出
退出服务    设置页按钮，与 Ctrl+C 同一条优雅关闭路径（隐藏控制台时唯一退出手段）
版本与更新  「检查更新」比对各节点自报版本 → 从该节点下载 zip → 解出本平台二进制
            并校验 → 替换本机二进制并重启

推送给节点  在本机 Web 上选一个节点 → 把本机的新版本按该节点的平台取出并上传 →
            写入替换脚本并让它自我替换重启。节点侧不需要新能力；
            推送与重启都会中断该节点与本机的连接，几秒后以新版本重连。
            若节点上执行不了命令（没有反向链路的独立发现节点），自动改走
            「它自己的 MCP」：本机把二进制挂到一次性下载端点（token 用后即焚、
            5 分钟过期），经该节点 56701 的 MCP 让它本机执行下载与替换重启。
            前提：本机与该节点同网段（它能访问本机的 56701）。

run 脚本行为
------------
  无 <数据目录>/hide_console 标记 → 前台阻塞，输出进控制台 + 日志
  有 <数据目录>/hide_console 标记 → 后台异步，输出只进日志，控制台可关

日志文件：<数据目录>/npa.log（超过 10 MB 自动轮转为 .1）

默认值（调试期，便于联调）
--------------------------
  MCP 服务范围       局域网（可在设置改回仅本机）
  MCP 能力           SSH / File / Tunnel / Screenshot / Mouse / Discovery / Relay 全部开启
  Discovery 服务     开启
  反向接入           开启，监听 0.0.0.0:56701
  Web 管理界面       仍固定 127.0.0.1:56700，不对外
  端口映射           本机入口默认 127.0.0.1，可按单条映射开启局域网

需要收紧时，在「设置」与「节点」页把上述开关改回即可。

数据目录
--------
默认：~/.npa（Windows 为 %USERPROFILE%\.npa）
自定义：npa --data-dir "D:\npa-data"

设置「恢复自动启动端口映射」为“是”时，重启后会自动恢复已启动的映射。

诊断参数
--------
npa --version          输出版本
npa --log-level debug  调试日志
npa --data-dir DIR     指定状态目录
npa -h                 查看帮助

文件与命令面
------------
上级对 peer 节点的文件操作（上传/下载/读/写）与命令执行，优先走节点 56701 上的
/api/file/* 与 /api/exec 纯 HTTP 接口（流式，大小不限；单次整读/整写的 read/write
仍限 4 MiB）。SFTP-over-WS 与 exec 通道降级为回退，避免大文件挤占 4 条通道池。
这些接口当前无鉴权（调试期），同网段可达者均可调用，正式使用前需收紧。

提示
----
本包只提供启动脚本与二进制；节点、映射、审计等数据全部保存在数据目录中，
不需要任何配置文件。
